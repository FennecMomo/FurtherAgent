# Hermes 兼容补齐（2026-10-13，源码阶段）

本次只修改源码并运行隔离测试，没有打包、安装、重启应用或部署 Hermes 服务器。当前上游 HTTP API 源码用于核对协议，不代表目标服务器已经升级到相同版本。真实服务器验收仍需在后续部署时完成。

## 已实现

| 项目 | 行为与边界 |
| --- | --- |
| 运行状态 | 区分排队、执行、等待审批、停止中、完成、失败和状态未知；桌面与手机使用同一状态灯映射。只有 FurtherAgent 持有的运行可以判定，其他入口的任务仍不可见。 |
| 接入端重启恢复 | 持久化原 run_id、待确认提交的原文、幂等键及完整请求体。重新打开原会话时查询原运行；不会自动重新提交。请求体被冻结，之后改变输出目录也不会改变原提交的幂等内容。 |
| SSE 续接 | 接收到事件序号后，断线携带 Last-Event-ID 重连并跳过重复事件；最多尝试 6 次。遇到 replay.truncated 显示缺失提示，完成后用历史核对。旧服务器没有序号时沿用状态轮询，不盲目重播。重启后重新读取保留事件，不把未持久化的文本缓冲冒充完整输出。 |
| 文件上下文 | 将输出目录及交付规则放入 Runs API 的 instructions；用户 input 保持原样，不再把整段文件工作区说明放进用户消息。附件依旧使用既有文件传输、校验和下载链路。 |
| 模型与思考强度 | 模型列表来自远端，只给声明 reasoning 能力的模型展示 Hermes 思考档位；仅允许声明 can_disable_reasoning 的模型关闭思考。写入会话模型锁并读回验证，服务器忽略参数时明确报错。档位由 Hermes 再映射为模型实际参数，不保证模型逐档区分。 |
| 历史与轮询 | 通过远端 offset 获取超过原 250 条窗口的历史，保留时间顺序；客户端继续使用已有分页协议。一次最多读取 8000 条原始记录、约 200 万显示字符、30 秒；达到上限明确提示。分页期间最新页变化则拒绝混合快照。没有分页元数据的旧服务器保留最近窗口。无观察者的空闲会话暂停历史请求；被查看的空闲会话首轮 15 秒、之后 30 秒刷新，活动运行状态仍每 2 秒查询。 |
| 运行用量 | 在设置中展示后端实际返回的输入、输出、总计与缓存 token，以及实际执行的模型（含回退模型）。没有数据时说明尚无记录；不虚构成本或套餐余额。 |

## Question 与余额的明确限制

当前官方 HTTP Runs API 提供权限审批回答接口，但没有普通 clarify / Question 的回答接口。因此本次只在收到 clarify 工具开始事件时显示澄清提示，并在工具结束或运行终止时清除；提示没有回答按钮，不把回答转换成审批或普通聊天消息。

**这不等于完成了普通 Question 交互。** 仅有工具 preview 时也不能保证拿到完整问题与选项。要实现问题、选项、回答和原问题关闭的完整闭环，需要 Hermes 服务端提供原生澄清回答通道，或者另外接入具备该能力的原生 gateway，并对目标版本进行联调。本次未修改用户正在使用的服务器。

当前 Hermes 接入也没有统一套餐余额接口。不同 provider 的余额需各自接口与授权，本次只展示运行 token 用量和明确的余额不可用说明。

工作空间与 TodoList 不在本次范围。

## 恢复记录与部署注意事项

- 生产 Host 默认把恢复目录放在设备 identity 文件旁，名称为 `<identity 路径>.hermes-runs`，可用 `FURTHERAGENT_HERMES_STATE_ROOT` 指定稳定目录。`--probe` 不写恢复记录。
- 目录按 Hermes 地址和凭据的哈希隔离，再按会话 ID 哈希分文件；不保存 API key 明文。记录包含待确认消息正文，应按私有应用数据保存。Linux 新目录权限 700、文件 600，写入采用临时文件、刷盘和原子替换。
- 升级时保留同一设备 identity 与恢复目录；更换 Hermes 地址、凭据或目录不会自动继承原归属。
- 记录损坏时阻止发送，不清空覆盖，也不猜测原任务已完成。远端 run 查询失败时继续保留记录、显示未知状态，不自动重发。
- 待确认提交超过 24 小时不再允许通过旧键重试，需在 Hermes 核实。停止、追加、审批仍不会自动重放。
- 共享层仍最多保留 128 个访问过的会话适配器；本次优化其空闲 HTTP 轮询，未加入适配器淘汰。
- 服务模板继续保留 `Restart=no`，没有在缺少真实服务器验收时改变运行策略。
