# 留言模块部署指令

本轮仅交付源码，由用户在家里电脑拉取并打包，不通过服务器递交安装包、不自动部署。以下指令仅供用户后续明确安排服务器/家里接入端部署时参考；安装包和源代码本身不代表线上已启用。

## 中继服务器

确认当前 FurtherAgent 中继的服务单元、用户、监听地址、运行目录、配置及现有连接。将新 Server/Core 部署到新的版本目录，保留旧目录和启动配置作为回退；只更新 FurtherAgent 中继，不重启 Hermes、dashboard 或其他服务。

设置独立的持久 `FURTHERAGENT_MAILBOX_ROOT`，位于运行用户可写的数据目录，不能放在随版本清理的发布目录。保留既有设备身份、域名、端口及代理配置。切换服务后检查 `/health` 的 mailboxVersion=1、persistentMailbox=true、softwareVersion 和既有 Host 重连。记录实际 DLL 路径、版本/哈希、数据目录及回退路径。只允许单实例持有同一留言目录。

## 家里 DSH / 小夜

安装新的 CLI，可不更改 DSH 本身。更新 FurtherAgent Host 会自动生成留言账户描述；若先只更新 CLI，用 `mailbox setup` 指向当前实际 Host 已有的身份文件，不新建或更换配对码。用 `mailbox accounts` 确认账户描述可读，并通过 `mailbox status` 验证连接。

给小夜说明：这是单独的被动留言箱；新留言只存储，不立刻启动任务。可以在自己已有的活动节奏中，自主决定何时 status/read、标已读和 reply；不新增定时器、不改变原会话唤醒计划。命令见 Mailbox.md。凭据留在私有文件里，不放进会话提示词。

## 线上最小验收

先完成一次在线绑定。使用明确标识的测试文字验证用户发送→小夜查收→显式已读→小夜回信→用户补收及通知。收件端退出 DSH/Host 后，用户端仍能保存留言；恢复后能查回同一消息。测试结束保留必要审计，不把真实私密留言写到公开日志或 Git。
