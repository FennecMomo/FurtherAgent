# 操作摘要与旧接入端正文分页

## 修复原因

0.14.6 只在支持 history-mode v3 的 B 端按正文计数；旧 B 端返回 v2 原始条目时，客户端一次加载仍只请求一个分页，导致整批只有工具记录。

桌面和手机现在共用 LoadBatchAsync：一次用户加载自动连续请求，直到累计至少 8 条用户/AI 正文，或已到历史开头。操作记录全部随同保留，不占正文额度；不拆分旧接口页面，因此最后一页可能让正文稍多于 8 条。逐页校验会话、版本、游标连续性和总数，异常不会合并错误历史。手机继续缓存单个接口页面。

## 展示

操作默认分组折叠，展开后只显示简短动作，不提供参数、原始 JSON 或结果正文。结构化记录可显示调用工具名称、文件新增/删除/修改路径、终端程序名、思考与上下文整理。无结构证据时使用概括，不从任意命令文本猜测删除等动作。失败与执行中状态保留。

移除按 16 KB 丢弃旧操作的策略，全部保留摘要；极长连续操作按每组 256 项分组，避免单组无限增大。正文与历史游标不因显示转换而改写。

## 验证

- 完整回归 420 项通过。
- 最后调整分组上限后，20 项历史/摘要专项再次通过，包含数千操作、旧接口连续空正文分页和无丢失游标检查。
- 18 项 WPF 历史/折叠/会话文件检查通过，确认展开操作不再有原始详情控件。
- Android Compile：0 警告、0 错误。

本次只修改、验证和本地提交，未打包安装或推送。客户端跨页兼容不依赖 B 端升级；旧 B 端若已经截断记录或未提供操作结构，无法恢复它未传来的内容。
