# 操作历史与会话文件折叠

2026-10-14，源码修改与验证；未打包、替换或推送。

## 行为

- Windows 桌面原先没有协商包含操作记录的历史模式，Codex 接入端默认只返回正文；现在与手机统一协商 history-mode v3，重连时重新协商，旧接入端回退到 v2。
- 连续工具、推理与系统记录在原时间位置合并为“X 项操作记录”，默认折叠，不越过用户/AI 正文合并。桌面展开后按需创建子项，子项本身也可折叠；同一历史位置的组保留手动展开状态。
- v3 每批按最多 8 条用户/AI 正文计数，操作组不消耗该额度。手机累计窗口按 32 条正文计数，桌面按 256 条正文计数，不再让操作记录挤占正文。历史游标仍对应实际返回条目，保持无缝分页、缓存校验与旧记录锚点。
- 单页仍有 1 MiB 传输保护；大批操作的详情预算为每组约 16 KB，优先保留最近操作，每项正文及原始字段各限制 1000 字符。摘要显示全部操作数量，被省略的详情数和内容截断会明确标记。极长正文仍受原字节上限约束。
- v1/v2 原协议输出不变；只有协商 v3 的客户端收到新的结构化操作组。
- 桌面和手机末尾的会话文件默认收为“会话文件 · N 个”一行，点击展开后保留原预览、保存/下载入口，文件列表高度有上限。文件变化保留用户手动展开状态；进入另一会话默认收起。

## 上线范围

显示与文件折叠需要更新 A 端客户端。按正文计数的 v3 历史需要 B 端接入程序同时更新；仅更新客户端、仍连接旧 B 端时可回退显示操作，但不能改变旧接入端的分页计数。此处“历史分页”是客户端阅读窗口，不改变模型的实际 token 上下文或计费。
