# 点对点直连

桌面 0.16.0、Android 0.14.0 和接入端 0.16.0 支持此功能。沿用现有服务器地址及配对码。客户端先使用已可用的局域网直连，否则通过中继连接，并在后台与接入端协商点对点直连。连接页显示实际承载会话数据的“局域网直连”“点对点直连”或“服务器中继”。

WebRTC ICE 通过 UDP 检查双方可用的地址。默认向 `stun.cloudflare.com:3478/udp` 查询公网地址和端口。STUN 服务能看到探测来源的公网地址，协商信息经已配对的 FurtherAgent 中继传递。数据通道完成 DTLS 证书指纹校验后，客户端还需通过 RPC 心跳才切换。直连建立后，会话、文件和图片都通过双方之间的加密通道传输。离线留言仍由现有服务器保存。[STUN 服务说明](https://developers.cloudflare.com/realtime/turn/)

点对点直连无需配置固定公网 IP 或路由器端口映射。阻止 UDP 的网络，以及部分双层 NAT 或运营商 NAT，仍可能无法直连。失败时继续使用现有中继。已经建立的直连断开后会重新选择连接，回到中继时至少等待 30 秒再尝试点对点直连。保持会话和历史同步，发送、审批、文件写入等原请求不会自动重放。正在处理的 RPC 或打开的 Mini 通道会推迟连接切换，直到当前通道空闲且 Mini 关闭。

需要停用探测时，在启动客户端或接入端前设置 `FURTHERAGENT_P2P=0`。可用 `FURTHERAGENT_STUN=stun:服务地址:端口` 指定自有 STUN，或设为 `off` 只试本机网卡候选地址。现有中继只承载协商和回退流量，无需部署新的服务端版本或开放云服务器 UDP 端口。
