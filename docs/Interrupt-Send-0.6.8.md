# 0.6.8：打断后发送与输入留白

- WPF 增加独立“打断并发送”按钮，保留运行中的“追加指令”和单独“停止”。
- CLI 增加 `interrupt-send --session ID --text TEXT`，与 WPF 共用 Core 的 SessionActions.InterruptAndSendAsync；附件参数与 send 一致。
- 仅支持本接入端持有、明确可停止的 Hermes run。先核对会话和运行 ID，停止一次，等待同一运行结束且恢复可发送，再提交一次新消息。
- 默认停止确认限时 90 秒；停止失败、超时、运行变化、连接中断均不继续发送。发送确认超时表示结果未知，不自动重发。WPF 保留未确认的输入与附件。
- 微信等其他入口的运行仍不能接管；不能把此功能解释为跨入口强制中断。停止也不能撤销已执行的工具操作。
- 输入框 Margin 动态绑定 FontSize / 2（13 DIP 字号对应四边 6.5 DIP），移除外层重复 Padding，保持左上对齐。

验证：Release 构建成功；137 项核心检查（含停止/发送顺序、附件路由、拒绝、超时、运行改变、非自有运行）；17 项 WPF/持久化检查及实际输入控件左上对齐、半字号 Margin 检查通过。预览为离屏渲染，无桌面窗口操作。

此次不修改远端 API 协议，不要求升级线上中继或 Hermes 接入端。当前业务运行正在执行，未对其做真实打断测试；本次打断顺序验证使用本地 RPC 测试端。
