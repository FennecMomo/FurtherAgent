# 文本增量同步

适用版本：Windows / Host / Core 0.14.24，Android 0.12.14。

## 行为

生成中的回复连续增加文字时，`session-sync v2` 保留已收到的正文，只发送新增的末尾文字。会话状态、审批、模型、附件等元数据仍随快照更新；此功能不代表每个包只包含裸文字。

正文改写、截短、角色或详情变化、操作记录变化，仍采用完整的变化消息。初次连接、切换会话和断线后的新连接先建立完整快照，再继续增量。正文很短、追加包反而更大时也使用原来的消息同步。

## 兼容和恢复

- 客户端请求 `session-sync { version: 2 }`；接入端只向协商 v2 的客户端发送文本追加包。
- 新客户端连接旧接入端时继续解码 v1。旧客户端连接新接入端时继续接收 v1，未协商同步的客户端仍接收普通快照。
- v2 复用 `session-update`，新增可选 `append: { length, text }`。`keep` 包括需要追加的那条已保留消息，`length` 必须等于它当前正文的 UTF-16 长度；`view.messages` 是其后的新消息或替换消息。
- 校验失败不更新本地基线；连接读取器关闭，正常自动重连流程重新读取快照。新连接使用新的编码器和解码器，不依赖断线期间丢失的追加包。
- 桌面主窗口、Mini、CLI 和 Android 都通过 Core 的 `RemoteDevice` 接收重建后的完整 `SessionView`。界面无需自行拼接文字。
- 恢复只重读会话和状态，不重发消息、停止、审批或其他业务操作。

## 验证范围

本轮只执行必要的协议检查、桌面与 Android Release 编译以及本机回环中继的流式/重连冒烟。使用专用测试会话，不操作用户的现有远程任务或网络设置。

具体结果和未验收项目见 [待测试清单](Pending-Tests.md)。线上设备流量、手机前后台、省电策略和实际公网切换尚需设备验收。要在真实部署中启用节省流量的效果，接入端与控制端都需要升级；仅更新客户端不会改变旧接入端已发出的消息大小。中继透明转发协议，无需为此改动中继配置。
