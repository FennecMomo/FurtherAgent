# 0.6.7 双端心跳与 Markdown

## 心跳与状态

输入区下方有独立状态区，不再只靠操作提示推断连接：

- 中继：独立 HTTP GET `/health`，要求 HTTP 成功且 `status=ok, mode=relay`；4 秒超时。
- 客户端 B：通过当前中继 WebSocket 发只读 `agents` RPC，验证 B 接入端实际响应；6 秒超时。兼容线上旧接入端，无需更新服务器，不调用 Agent、不生成会话或消息。
- 两个检测循环独立运行，每轮结束后等 5 秒再检测。界面定期刷新在线/检测中/超时、上次成功距今秒数和往返耗时。
- B 超时但 WebSocket 未关闭时显示“响应超时（可能繁忙）”，不能将排队或拥塞误报成确定掉线。连接已断则显示“断线 / 重连中”。
- 在线仅证明对应健康接口或 B 接入端收到并回应，不保证模型供应商或 Hermes 当前推理成功。
- 另列活动状态：正在连接、会话加载、文件传输、提交操作、Agent 执行/生成回复、等待审批、等待指令。其他入口发起的 Agent 运行仍不可见，界面保留该说明。
- 本机 `Client-Control.ps1 -Action Status` 同时提供 relayHeartbeat、hostHeartbeat 和 activity，便于后台诊断。

## Markdown

服务器返回字符串内容，客户端不需要额外的 Markdown 格式标志。AI 正文一直进入原生 WPF Markdown 控件，本次补充下划线强调、删除线、任务项和有序列表缩进；标题、引用、粗体、代码块、表格、HTTP 链接继续渲染。思考正文也使用 Markdown，并保持默认折叠。原始 JSON/调试字段仍放在单独的原始字段视图，HTML 和本地文件链接不会作为可执行内容或自动加载资源处理。

这是常用 Markdown 子集，不宣称完整 CommonMark、LaTeX 或 Mermaid 支持。
