# Codex 模型、思考强度与套餐限额

Windows 0.13.0 / Android 0.11.0。控制端和负责接入 Codex 的 Windows 端均需要升级；中继不需要改变。旧端缺少的能力不会凭空显示为可配置。

打开会话后进入“模型与模式”：

- 模型列表来自接入端同一 Windows 用户、同一 CODEX_HOME 的 Codex `model/list`；读取所有分页，去重并排除隐藏模型。Codex 模型通过下拉框选择，读取失败时显示错误并允许刷新，不要求手填。
- 思考强度来自各模型的 `supportedReasoningEfforts`，包含接口实际提供的 low、medium、high、xhigh、max、ultra 等。切换模型后保留受支持的选择，否则切到该模型默认值；接入端再次校验，拒绝不支持的组合。设置通过桌面 IPC 应用到后续轮次，执行中的会话禁止修改。
- 套餐限额来自接入端的 `account/rateLimits/read`。优先显示每个限额桶，兼容单桶旧响应；用 `100 - usedPercent` 显示剩余比例，按真实窗口长度显示时长和本地时区重置时间。未知数据不会显示为满额或无限额。显示的是远端账号共享限额，不是本会话单独的余额，不执行购买或额度重置。
- 两端都可刷新模型与限额；CLI configure 新增 `--reasoning-effort`。其他 Agent 原有设置路径保持兼容。

验证：模型分页、隐藏/重复模型、思考强度兼容性、限额换算/缺失/多桶、旧协议兼容共 10 项自动检查。实际 WPF 设置窗口检查了选模型、回显当前强度、切换模型后删除不支持的选项及限额显示。

2026-10-12 的真实测试：通过公网中继从本机 Codex 接入端读回 7 个模型、思考强度和账号限额。初次 WebSocket 连接超时，重试成功。独立空白测试会话通过原生 IPC 写入 GPT-6.1 Sol / Plan / ultra 并读回一致，之后恢复原模型和模式；未发送任务消息。空白测试会话由桌面归档清理，不能用另一个元数据进程抢占桌面 writer。

Android APK 已构建；本次没有连接 ADB 设备，未做手机实机点击验收。既有异步 Question 原生旧卡片状态同步限制不在本次修复范围，不能将这些设置验证当作该问题已解决。
