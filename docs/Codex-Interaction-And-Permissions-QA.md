# Codex 消息同步与会话权限

验证日期：2026-10-14。源码修改；未打包、安装或推送，未修改真实会话的权限。

## 改动

- 接入端转换已接受的 `steeringUserMessage`，显示为用户消息。按服务器消息 ID / 客户端消息 ID 与普通用户消息去重，不按正文去重；未接受和失败的插入消息不会伪装成发送成功。
- 每次原生提交使用独立客户端消息 ID。若快照已返回对应的普通用户消息或 accepted steering，即使 IPC 回复仍在等待，也能完成发送确认。迟到的 IPC 异常会被观察；不自动重发。无确认、无对应快照时仍保留失败/未知结果。
- 桌面端确认成功时同步清理已保存的旧草稿，只清理本次附件。延迟确认不覆盖其他设备、其他会话或后来编辑的新草稿；打断后发送使用相同规则。
- 手机端捕获发送时的连接、草稿键和附件 ID，只清理原提交的内容，保留等待期间新输入的草稿和新附件。
- 两端会话设置新增只读、工作区写入（按需确认）、完全访问（无需确认）。单独点击“应用权限”生效；执行中拒绝修改，后续轮次使用新设置。自定义/未知权限明确显示，旧接入端隐藏入口。
- 使用 Codex 的 `thread-follower-update-thread-settings` v2 接口更新 `permissions`、`activePermissionProfile`、`approvalPolicy`，不混入模型、模式或思考强度配置。经共享接入适配器和中继转发。
